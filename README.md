# dsh-edit-diff

跟随 AI 的改动，并排展示 diff，**不破坏内置的语法高亮与 Markdown 渲染**。

English | 中文

![icon.svg](icon.svg)

## 为什么要重做

`dsh-follow-edits` 会在 Sidebar 预览里把改动的行标黄、删除的内容标红，但它的做法是：

```js
ctx.documentPreviews.register({
  extensions: ['ts','md','py', ... 约 60 个文本后缀],
  priority: 'extension',   // ← 这个 band 压过内置的 code / markdown 渲染器
  ...
})
```

`sidebar.right.tab.document` 是按实现 id 分发的 keyed slot，渲染器按
`extension > builtin > fallback` 的优先级排序。于是这个纯文本渲染器**顶替**了内置的
代码渲染器和 Markdown 渲染器 —— 结果是：

- 代码没有语法高亮
- Markdown 不再渲染，只显示原始文本

而内置的文档预览**没有提供逐行装饰（decoration）的扩展点**，插件能改的只有「换掉整个渲染器」。
所以「在原生预览里高亮 diff」这条路在当前 dsh 里走不通。

## 本插件的做法

插件**从不注册 `documentPreviews` 渲染器**，改用两条互不干扰的路径：

| 路径 | 机制 | 结果 |
|---|---|---|
| 原生预览跟随 | `ctx.sidebarRight.openResource(address, { params: { line } })` | 用内置渲染器打开文件，高亮/Markdown 全部保留，并跳到改动行 |
| 并排 diff | 注册独立的 page 类型 `editDiff.tab` | 左「修改前」右「修改后」，行级 +/− 着色 + 语法高亮 |

因为 diff 是一个**独立的 page 标签**（不声明 `patterns`，不接管任何扩展名），它和内置预览
并存，互不影响。

## 功能一览

| 区域 | 能力 |
|---|---|
| 形态 | 独立 `editDiff.tab` 页面；并排左右两栏；同一行配对显示改动的「左删 / 右增」 |
| 记录来源 | 编辑工具（`edit` / `write` / `multi_edit` / `apply_patch` / `str_replace_editor`）+ shell 命令（命令文本启发式解析 + `fs.watch`） |
| 对比语义 | 一轮内累积（对比本轮首次编辑前）、跨轮重置；新建文件=整份新增；删除/无基线不列表 |
| 多文件 | 一轮内每个文件一个可折叠分组，带 +/− 统计与文件计数；支持全部折叠/展开 |
| 跟随 | 三档自动打开（每次 / 每轮首次 / 关闭）；可单独关闭「原生预览标签」 |
| 跳转 | ▲/▼ 按**差异块**跳，序号 `3/7` 常显，当前块叠浅黄指示层，首尾回绕 |
| 视图 | 行级红/绿着色；6 类语言词法高亮；行号槽按最大行号位数自适应 + 竖分隔线 |
| 滚动 | 纵向只留中间一条竖条、左右逐行联动；横向共享列位置并按各自 max 截断 |
| 元信息 | 标题/简介来自 `locale/*.json` 的 `meta`；图标来自 package.json 顶层 `icon` |

## 语法高亮

diff 标签自带一个轻量词法高亮器（`LANGS` / `tokenizeLine`），支持 C/C++、JS/TS、Python、
Rust、Shell、JSON，**零依赖**：

- 内置预览的高亮来自 `ui-primitives` 的 `CodeBlock`，而插件规范禁止 `require` 那个包
  （它会随时改版、且没有类型检查）
- 实现方式是「先标记字符串/注释等受保护区间，再在区间外匹配关键字与数字」，
  避免把字符串里的 `if` 染成关键字
- 明暗两套配色，跟随 `body[data-ds-dark-theme]` 实时切换
- 按行分词；C 风格块注释跨行时按状态延续（整行按注释着色），多行字符串不回渗
- **每行分词后必须无损还原原文**，有测试锁住这条

未知后缀不高亮，保持纯文本。

## 改动从哪里来

Host 半（`index.js`）用一个 `sessionProjections` 单元记录改动，通过 `wire.view` 推给 Client：

- **编辑工具**（`edit` / `write` / `str_replace_editor` / `multi_edit` / `apply_patch`）：
  折叠 `tool/call` + `tool/result`。
- **shell / 脚本命令**（`pwsh` / `bash` 等）：`tools/pre-execute` 对**所有工具**都触发，
  所以命令执行**之前**会先从命令文本里解析出可能被写入的文件（`extractCommandPaths`），
  抢在原文消失前快照。解析是启发式的：按空白与常见分隔符切词，取像路径的 token
  （有已知文本扩展名，或带目录分隔符），忽略 URL、开关参数和二进制后缀。
  宁可多快照几个，也不漏掉真正被改的。
- 命令执行**之后**再由 `tools/post-execute` 把同一批候选路径**重新读一遍**与基线比对。
  这一路不依赖 `fs.watch`，所以**工作区之外**（命令里写了绝对路径、或 `workdir` 指向别的目录）
  的写入也能识别，并且不受「先截断成 0 字节、再写入」的时序影响。

### 为什么不能真正做到「任意手段全覆盖」

`fs.watch` 是**事后通知**：命令跑完、文件已改写才触发；它也只挂在会话工作区根上。
想拿到改动前的内容，只能在命令执行前主动快照，而 shell 命令是黑盒——插件看不到它
到底会碰哪些文件，只能靠命令文本猜。所以「命令后置回读」解决了**工作区外**与时序问题，
但「路径不在命令文本里」仍然无解：

| 情况 | 能否对比 |
|---|---|
| 命令里写着目标文件路径（含工作区外的绝对路径） | ✅ |
| 路径在脚本内部（如 `python gen.py` 写别的文件） | ⚠️ 只能快照 `gen.py` 本身 |
| 路径由变量拼接、运行时才确定 | ❌ |
| 命令完全不含路径（`make`、`npm run build`） | ❌ 只能事后捕获，无基线 |

### 修改前的内容是真实读取的

被删的内容在编辑后就不在文件里了，所以 `tools/pre-execute`（改之前）会**把整个文件读一遍**
存下来，作为 diff 的「修改前」基线。这比早期版本靠 `indexOf(newStr)` 反推可靠得多：

| 场景 | 只有反推 | 有基线 |
|---|---|---|
| 普通 `edit` | ✅ | ✅ |
| `write` 覆盖已有文件 | ❌ 看不到原文 | ✅ |
| 文件行尾符被改过 | ❌ 反推失败退化成全新增 | ✅ |
| 编辑后再被外部改动 | ❌ 定位不到 | ✅ |

只有拿不到基线时（读文件失败、或超过 2 MiB）才退回反推。

### 一轮之内持续对比最初版本

同一文件在一轮里常被连续编辑多次。插件按会话记住每个文件**本轮首次编辑前**的内容
（`turnBaseline`），后续编辑都对比这一份，用户看到的是整轮累积的完整对比，
而不是「上一次 → 这一次」的碎片。

`agent/turn-stopping` 时清空该会话的基线，下一轮重新取——所以每轮都是一次独立完整的对比。

### 自动弹出 + 持续刷新

- **首次编辑**：弹出侧栏、打开原生预览跳到改动行、并打开 diff 标签（会抢焦点）
- 只想看并排对比、不想让侧栏堆满原生预览标签时，在「设置 → 插件 →
  dsh-edit-diff → 配置」里关掉 **同时打开原生预览标签**：diff 标签照常自动弹出并抢焦点，
  原生预览不再打开（偏好存在 `localStorage: dsh-edit-diff:native`，改完立即生效）
- **连续编辑**（700ms 内）：复用同一个 diff 标签刷新内容，用 `revealIfOpened: false`
  更新但不抢焦点，避免打断用户
- diff 标签每次拿到新导航都会重读磁盘，所以右栏始终是最新内容

### 设置项（插件详情页）

都在「设置 → 插件 → dsh-edit-diff → 配置」里，纯客户端偏好（localStorage），改完立即生效：

| 设置 | key | 默认 | 作用 |
|---|---|---|---|
| 自动打开 | `dsh-edit-diff:follow` | `turn` | `always` 每次编辑都弹；`turn` 每轮首次弹；`off` 只更新不弹 |
| 同时打开原生预览标签 | `dsh-edit-diff:native` | `1` | 关掉后只弹 diff 标签，不再为每个文件开原生预览 |
| 调试信息 | `dsh-edit-diff:debug` | `0` | 显示「shell 改动没有基线」之类的内部提示 |

### 差异跳转（按块）

- 表头的 ▲/▼ 按**差异块**（hunk）跳，不是逐行：连续改动只算一处，
  跳一次走完整块
- 块序号 `3/7` **常显**：打开标签时就默认停在第 1 块（不用先点 ▼），
  之后随 ▲/▼ 移动
- 当前块会盖一层**浅黄半透明**底色（`rgba(255,199,0,0.26)` 的
  `backgroundImage`），叠在红/绿底色**之上**而不是替换它，
  所以「哪一段是当前块」和「哪几行增/删」能同时看到
- 横向两栏同时着色，纵向联动滚动；到首/尾会回绕

### 滚动条

- 纵向滚动条**只保留两栏中间那一条**：右栏的竖条用样式表隐掉
  （`[data-cline-pane="right"]::-webkit-scrollbar:vertical`），滚动能力不变，
  仍由左右联动同步
- 横向滚动条两栏各自保留，但**共享同一个列位置**：拖动任一栏，另一栏跟到同一列，
  然后按各自的最大可滚动距离截断。三种典型结果：
  - 拖**短**栏到底 → 长栏跟到同一列；短栏停住，再拖长栏可继续右移，短栏被钉住不动
  - 两栏都在最右，左移**长**栏 → 短栏一直钉住，直到长栏回到短栏的列位置才一起左移
  - 两栏都在最右，左移**短**栏 → 长栏直接跟到短栏的列位置

### 行号槽

- 宽度按**最大行号位数**算（`ch` 单位；等宽字体里 1ch 正好一位数字），不再写死 `3.2em`
- 左右两栏共用同一个宽度，保证两栏代码文本的左边缘对齐
- 行号与代码之间有一条 1px 竖分隔线（`--dsw-alias-border-l1`），亮/暗主题自适应
- 对侧缺失的行用 `NBSP` 占位，行高不塌，纵向仍逐行对齐

## 安装

```text
plugin_manager  action: install_bundle  target: <你的路径>/dsh-edit-diff
```

安装后把旧的 `dsh-follow-edits` 关掉，否则它仍会顶替内置渲染器：

```text
plugin_manager  action: set_bundle  target: dsh-follow-edits  enabled: false
```

本插件**没有运行时依赖**（不依赖 `zod`）：链接安装的目录解析不到 profile 的
`node_modules`，任何外部依赖都会让 host 半 import 失败。

## 验证

```text
npm test              # 等价于 node test/run.mjs：递归跑 test/**/*.test.mjs 并汇总
node test/run.mjs diff   # 只跑主题目录名或文件名里含 "diff" 的套件
```

测试按主题分目录（`diff/`、`projection/`、`shell/`、`client/`、`turn/`、`newfile/`、`misc/`）：

```text
node test/run.mjs projection   # 工具参数解析、投影状态机、多文件、注入守卫
node test/run.mjs client       # 装载、跟随、折叠、同步、块跳转、行号槽
node test/run.mjs shell        # 命令路径解析、改动快照、fs.watch
node test/run.mjs turn         # 单轮基线、跨轮重置、漂移
node test/run.mjs newfile      # 新建文件、Markdown 新文件
```

- 夹具一律写在系统临时目录（`os.tmpdir()`），跑完自动清理，不依赖本机路径
- 用例读的是 `dsh-edit-diff/client.js`（相对仓库父目录），`run.mjs` 会统一设好子进程 `cwd`

## 已知取舍

- **diff 标签是独立页面**，不会嵌在原生预览里 —— 原生预览没有装饰扩展点，这是唯一不破坏高亮的选择。
- **新建文件**只能看到「新增」，没有「修改前」一侧。
- **shell 改动**只有在命令文本里能解析出目标路径、且执行前成功快照到原文时才做完整对比；
  路径藏在脚本内部、运行时拼接、或命令根本不含路径（`make`、`npm run build`）时只能事后捕获，
  拿不到基线的条目**不显示**（避免空栏目噪音）。
- **高亮是按行词法**，块注释跨行时按状态延续、多行字符串不延续；只覆盖 6 类语言，其余后缀纯文本。
- **删除动作没有独立视图** —— 删除后文件不存在，diff 标签只显示「文件已不存在」。
- 原生预览跳行：Markdown 渲染器不支持行锚点，只有纯文本和代码渲染器会响应 `line`。
- 上限：基线整份读取 2 MiB；随导航参数携带的原文 256 KiB（超了回退读盘）；一轮内最多 64 条 shell 改动。
- 横向联动依赖 `scroll` 事件，程序化写 `scrollLeft` 会产生回声，已用「记住自己写入值」的方式抑制。
